Status lifecycle

To do → In progress → Done ↩ back transitions allowed
Allowed transitions
To do→ In progress only
In progress→ Done or back to To do
Done→ back to In progress
Transitions are enforced at the domain layer — the frontend dropdown shows only valid next states.

Create task

1
Click "+ New task"
Inside a project view. Opens a creation form.
2
Fill in title, assignee, due date
Status defaults to To do. Title required, rest optional.
3
Submit → task created
Appears in project list. Assignee notified in-app if set.

Change status

1
Open task detail
Click the status badge to open transition dropdown.
2
Dropdown shows valid states only
Not all statuses — only valid transitions from current state.
3
Transition applied
Domain event dispatched via Messenger. Assignee notified.

Invitation lifecycle

Pending → Accepted / Declined / Expired after 7 days

Owner invites a member

1
Owner opens Members → Invite
Enters email and selects role (member or guest).
2
Invitation created — Pending
Unique token generated. Expires in 7 days.
3
In-app notification sent
Only if invitee already has an account (v1 constraint).
4
Invitee accepts or declines
Accept → joined with role. Decline → owner can reinvite.
5
Expiry path
No action after 7 days → Expired. Owner can reissue.

Technical notes

Notifications are delivered in real-time via Mercure (bundled in FrankenPHP). The frontend subscribes to the Mercure hub on load.

Events are dispatched asynchronously via Symfony Messenger. Adding email notifications in v2 is additive — a new handler on existing events.
